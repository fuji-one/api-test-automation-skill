# 阶段输入输出契约

## 阶段定位

`executable-interface-case-set` 是 AI 端到端 API 自动化流程中的“执行级接口用例集生成”阶段。它承接设计级接口用例和契约材料，补齐真实入参、预期出参、断言、变量链路、前置数据和清理策略，产出可转 pytest+allure 的执行级用例集。产物准出后，只允许下游补充环境配置、pytest 工程规范和 allure 标注规范。

本阶段不生成 pytest 脚本。下游 pytest+allure 代码生成阶段只能在本阶段状态为 `PASSED` 时继续。

## 输入契约

### 必需设计输入

| 文件或来源 | 必需 | 说明 |
|---|---|---|
| `case_list.yaml` 或 `测试用例清单.md` | 是 | 优先读取 `case_list.yaml`；设计级接口测试用例，含请求方式、接口、测试点、Schema、断言方向和覆盖追溯字段 |
| `执行报告.md` | 是 | `gated-interface-testcases` 阶段报告，必须为 `PASSED` |
| `接口结构化契约清单.md` | 是 | method、path、参数、响应、状态码、错误码、接口规则 |
| `接口测试用例设计文档.md` | 是 | 测试点、覆盖对象、流程、断言来源 |
| `数据模型.md` 或数据库结构 Markdown 文档 | 是 | 表、字段、主键、唯一键、索引、枚举、状态、逻辑删除字段、归属键、轻量表关系知识图谱、铺数顺序、清理逆序、清理边界，必须为 UTF-8 Markdown |
| `required_chain_flows.yaml` | 按上游产出 | 已确认必须生成链路脚本的权威分母；只有其中的 required flow 能作为执行级链路脚本准出依据 |
| `chain_flow_candidate_audit.yaml` | 按上游产出 | 候选链路进入或未进入 `required_chain_flows.yaml` 的审计说明 |
| `business_scenario_map.yaml` | 是 | 业务链路候选和上下文参考；`flow_generation_required=true` 或 `chain_type=e2e_flow_candidate` 不能单独作为必须生成链路脚本的依据 |
| `业务场景链路清单.md` | 是 | 供人工确认的业务链路视图，必须与候选链路的接口链路和 `flow_id` 一致；不能替代 `required_chain_flows.yaml` |
| `测试覆盖点报告.md` | 按上游产出 | 覆盖参考材料，只能辅助发现候选链路和覆盖风险，不能作为链路脚本准出依据 |
| 运行时取证规划 | 可选 | 读取 `04-runtime-evidence-plan/` 中的风险审计、DB 前后探测计划和阻塞候选；只能用于追踪 request-allowed、manual-confirm/blocker、清理和 DB evidence 缺口，不能提供运行值 |
| 运行时取证证据 | 可选 | 辅助补充登录 token、业务 ID、状态字段、业务码、枚举码、错误码、返参字段值；仅上游已生成 `04-runtime-evidence/` 或执行事实引用 `live_request_evidence` 时读取 |
| Apifox MCP | 可选 | 辅助读取接口契约、测试用例、保存用例和响应示例；仅用户要求 Apifox 对齐或执行事实引用 `apifox_mcp` 时必需 |

### 前置校验契约

进入执行级用例生成前必须完成以下校验，并将结果写入 `前置数据构造规则.md` 的 `## 输入前置校验`：

| 校验项 | 必需结果 | 说明 |
|---|---|---|
| 文档完整性 | 通过 | 必需 Markdown 文档存在、可读、非空、UTF-8、无乱码 |
| 设计级准出 | 通过 | `执行报告.md` 阶段状态为 `PASSED` |
| 用例基础字段完整性 | 通过 | 设计级用例字段齐全 |
| 主要流程字段完整性 | 通过 | 主流程有触发条件、接口链路、前置数据、成功响应和关键断言 |
| 异常流程字段完整性 | 通过 | 异常流程有异常条件、请求变体、契约错误码或状态码、错误断言 |
| 契约完整性 | 通过 | method、path、参数、响应、状态码、错误码可追溯 |
| 数据模型完整性 | 通过 | 表、字段、主键/唯一键/索引、枚举、状态、逻辑删除字段、归属键、轻量表关系知识图谱、铺数顺序、清理逆序、清理边界可识别 |
| 表关系知识图谱完整性 | 通过 | 涉及数据库铺数、断言或清理的表均能定位父子关系、业务归属、构造顺序和清理逆序；无法确认时必须阻塞 |
| 链路场景完整性 | 通过 | `required_chain_flows.yaml` 中已确认必须生成链路脚本的场景均能映射到执行级有序步骤、生产者/消费者变量链路、提取规则、注入目标、链路断言和清理边界；候选材料和 `测试覆盖点报告.md` 仅作参考 |
| 运行时取证规划状态 | 未使用/通过/有阻塞 | 使用 requester-backed planning 时，必须把 `runtime_blocker_candidates.yaml` 中 required fact 对应项转为阻塞或人工确认项；`runtime_request_plan.skeleton.yaml` 不得直接作为请求计划执行 |
| 运行时取证证据状态 | 未使用/通过/部分通过/不通过 | direct requester 未使用时不阻塞；使用时只消费 `confirmed` 且 `usable_for_execution_case=true` 的值；用户要求运行时取证但环境、鉴权、服务或证据冲突不可用时阻塞 |
| MCP 连接状态 | 未使用/通过/部分通过/不通过 | Apifox MCP 未使用时不阻塞；使用时记录可读取的证据等级和缺口；只有用户要求 Apifox 为准时，缺少项目或接口范围才阻塞对应范围 |
| 鉴权账号与清理输入 | 通过 | 鉴权账号、token 获取规则、清理策略足以支撑可重复执行 |

任一必需项不通过时不得标记 `PASSED`。

### `PASSED` 必需执行输入

| 输入 | 必需内容 | 允许来源 |
|---|---|---|
| 环境引用契约 | base URL、网关前缀、超时、证书、公共 header 的变量名或占位引用；真实环境值可由下游注入 | 用户文件、Apifox 环境、CI 配置 |
| 鉴权账号配置 | 登录方式、账号池、角色、租户、权限、token 提取 | 用户文件、Apifox 测试用例、鉴权接口契约 |
| 接口传输加解密策略 | 确认加密接口、确认明文接口、算法引用、key 来源、请求明文范围、请求序列化方式、请求包装字段、响应解密字段和解析规则；若请求为整体参数字典加密，必须记录公共参数 + 业务参数合并后序列化为 JSON 字符串再加密；若响应为 `data` 字段密文，必须记录仅解密字符串型 `data` 并解析为 JSON 对象 | 用户确认、执行配置、网关/客户端协议、算法目录、源码传输策略 |
| 测试数据配置 | 正常值、边界值、枚举值、非法值、唯一值规则；正向和页面可见字段使用合法真实值，普通展示/资料字段才可使用通用真实样例，非法/占位值仅用于错误分支 | 用户文件、数据模型 Markdown、按需 Apifox 示例、运行时证据、字典/配置接口、DB 有界样本 |
| 变量提取/注入规则 | JSONPath、数据库字段、后续注入路径 | 设计流程、运行时证据、数据模型 Markdown |
| 精确断言规则 | HTTP 状态码、业务码、字段值、关系、数据库或事件断言 | 契约、设计文档、按需 Apifox 响应、用户规则 |
| 清理策略 | API/SQL/状态恢复方式、顺序、失败处理；数据库清理必须引用归属键、清理身份和清理逆序 | 用户文件、数据模型 Markdown、清理接口契约 |

缺少任一 `PASSED` 必需执行输入时，阶段状态必须为 `BLOCKED_NEED_EXECUTION_INPUT`，不得声称可直接生成可运行 pytest 脚本。运行时取证证据缺失只能阻塞用户明确要求的 direct requester 补值范围；Apifox MCP 不可用、环境未读出、无保存用例或鉴权变量缺失时，只能阻塞用户明确要求的 Apifox 对齐范围。当必需执行输入已由用户配置、结构化契约、设计材料、运行时证据或数据模型证实，不得仅因 Apifox 缺口阻塞。真实环境配置、pytest 工程规范、allure 标注规范是准出后允许下游注入的三类外部输入，不作为本阶段 `PASSED` 阻塞项，但必须在 `脚本生成准出门禁` 中明确列为唯一外部补充项。

## 输出契约

默认输出目录必须包含以下 Markdown 文件和结构化 sidecar：

| 文件 | 必需 | 说明 |
|---|---|---|
| `执行级接口用例集.md` | 是 | 可转 pytest+allure 的执行级用例，失败时不得包含最终用例 |
| `前置数据构造规则.md` | 是 | 数据准备、变量链路、环境鉴权需求、清理策略、准出结论 |
| `stage_status.yaml` | 是 | 阶段状态、准出、输入输出、门禁和阻塞项 |
| `coverage_matrix.yaml` | 是 | 设计级到执行级的覆盖继承、计数、缺失项和映射 |
| `execution_fact_sources.yaml` | 是 | 环境/鉴权人工输入状态，以及 token、数据、变量、断言、清理事实来源 |
| `apifox_evidence_index.yaml` | 按需 | 当执行事实来源包含 `apifox_mcp` 时必需，记录证据等级和冲突优先级 |

当用例数量过大或用户明确要求分片时，允许启用分片输出。分片输出仍必须保留上述根产物和 sidecar，并且只允许额外包含：

| 文件或目录 | 必需 | 说明 |
|---|---|---|
| `执行级用例分片索引.md` | 是 | 机器可读的分片顺序索引 |
| `执行级用例分片/` | 是 | 按索引顺序存放分片文件 |

分片输出的读取顺序固定为：`执行级接口用例集.md` -> `前置数据构造规则.md` -> `执行级用例分片索引.md` -> 按索引 `顺序` 字段从 `001` 递增读取分片文件。下游不得依赖文件系统自然排序。

## 阶段状态

| 状态 | 含义 | 是否允许进入 pytest+allure 代码生成 |
|---|---|---|
| `PASSED` | 所有执行级信息完整并通过可重复执行校验 | 是 |
| `FAILED_DESIGN_GATE` | 设计级报告未通过或必需设计输入缺失 | 否 |
| `FAILED_CONTRACT_GATE` | 契约、设计、已使用 Apifox 证据、数据模型存在阻塞冲突 | 否 |
| `BLOCKED_NEED_EXECUTION_INPUT` | 缺少环境、鉴权、真实值、断言或清理策略 | 否 |
| `BLOCKED_NEED_CHAIN_FLOW_EVIDENCE` | 必须生成链路脚本的场景缺少有序步骤、变量提取/注入、链路断言或清理边界 | 否 |
| `FAILED_EXECUTION_READINESS` | 用例不可重复执行或不可稳定转 pytest+allure | 否 |

### 非 `PASSED`

文件必须保持 case-free，只包含：

```markdown
## 执行级接口用例集

- 阶段状态：...
- 生成状态：未生成
- 原因：执行级门禁未通过，详见 `前置数据构造规则.md`
```

所有状态都必须包含：

- `## 阶段结论`
- `## 输入前置校验`
- `## 输入完整性检查`
- `## 数据模型索引`
- `## 环境与鉴权配置需求`
- `## 前置数据构造规则`
- `## 变量提取与注入规则`
- `## 链路脚本生成证据`
- `## 清理策略`
- `## 可重复执行校验`

- `## 缺失数据与待确认项`

非 `PASSED` 状态必须列出阻塞项、影响和修正建议。

## 准出规则

只有同时满足以下条件时才能标记 `PASSED`：

- 设计级 `执行报告.md` 为 `PASSED`
- 输入前置校验全部为通过
- 每条设计级用例都映射到至少一条执行级用例
- 每条执行级用例都有完整真实入参
- 每条执行级用例都有来源绑定的预期响应和断言规则
- 每条多接口链路都有变量提取和变量注入规则
- `required_chain_flows.yaml` 中每条已确认必须生成链路脚本的业务场景都有执行级 `链路flow_id`、连续步骤序号、生产者/消费者关系、链路断言和清理边界
- 每条用例都有可执行前置数据构造规则
- 每条用例都有清理规则或明确无需清理的来源依据
- 正向主流程、live 用例、长链路和页面可见字段不得使用明显占位值；若使用非法/占位值，必须是异常分支并有对应错误断言
- 涉及数据库铺数、SQL、数据库断言或清理的用例，都有表结构、轻量表关系知识图谱、归属键、铺数顺序和清理逆序依据
- 鉴权账号配置和 token 获取规则完整
- 若存在确认加密接口，接口传输加解密策略完整：算法引用、key 来源、请求明文范围、请求 JSON 序列化、请求 `data` 包装、响应 `data` 解密解析规则均已确认
- 仅缺少环境配置、pytest 工程规范、allure 标注规范三类外部输入
- 未使用运行时取证时无 direct requester 阻塞项；已使用运行时取证时，运行时值与结构化契约、设计依据、数据模型无阻塞冲突
- 未使用 Apifox 时无 Apifox 阻塞项；已使用 Apifox 时，Apifox 契约、保存用例或响应示例与结构化契约无阻塞冲突
- 用例集包含足以生成测试函数、请求调用、断言、setup、cleanup 和参数化数据的字段

## 下游边界

下游 pytest+allure 代码生成阶段可以使用本阶段产物生成脚本，但不得从字段类型、JSON Schema 或 HTTP 常识臆造真实值。若本阶段状态不是 `PASSED`，下游只能生成修复建议，不能生成可运行脚本。即使本阶段为 `PASSED`，下游仍需外部提供环境配置、pytest 工程规范和 allure 标注规范后才能执行。
